# سند طراحی — NEON CAD (نرم‌افزار طراحی و آماده‌سازی تابلو نئون)

> نسخه MVP — پیش از کدنویسی تهیه شده است.
> هدف: طرح دیجیتال → مسیر واقعی نئون → اصلاح هندسی → نقاط برش واقعی → تقسیم به قطعات → Cut List → متراژ کل → محاسبه برق → فایل آماده ساخت

---

## 1. معماری کلی

- **یک Cloudflare Worker تک‌فایلی** (`worker.js`) که کل اپلیکیشن (HTML + CSS + JavaScript) را درون‌خطی سرو می‌کند.
- **تمام پردازش‌های هندسی سمت مرورگر** انجام می‌شود (بدون سرور و بدون وابستگی به CDN) — پروژه‌های ساده بدون هیچ سرویس جانبی کار می‌کنند.
- اتصال مخزن GitHub به **Cloudflare Workers Builds** برای استقرار خودکار با هر push.
- ذخیره‌سازی پروژه‌ها و پروفایل‌های نئون در `localStorage` + Export/Import فایل JSON.

```
┌──────────────────────────────────────────────────────────┐
│ TOP BAR: پروژه | AUTO/MANUAL | CHECK DESIGN | PRINT/PDF  │
├────────┬─────────────────────────────┬───────────────────┤
│ TOOLS  │           CANVAS            │    PROPERTIES     │
│ Select │   (مقیاس واقعی، بر حسب cm)  │ Width / Height    │
│ Pen    │                             │ Neon Width        │

```

## 2. سیستم مختصات و مقیاس واقعی

- فضای کار (Board) **بر حسب سانتی‌متر** است. مبدأ: گوشهٔ بالا-چپ، Y به پایین (سازگار با Canvas و SVG).
- ابعاد تابلو توسط کاربر تعیین می‌شود (مثلاً `200 × 100 cm`)؛ همهٔ اندازه‌ها، طول‌ها و خروجی‌ها بر همین مبنا هستند.
- نمایش روی صفحه با Zoom مستقل (px per cm) انجام می‌شود ولی **خروجی‌ها همیشه مقیاس واقعی ۱:۱** هستند:
  - SVG: `width="Wcm" height="Hcm"` + `viewBox="0 0 W H"`
  - DXF: بر حسب cm (هدر `$INSUNITS = 4`)
  - چاپ/PDF: برگهٔ A3/A4 با یادداشت مقیاس

## 3. ساختار داده (Data Model)

```js
Project = {
  version: 1,
  name: "Untitled",
  board: { widthCm: 200, heightCm: 100 },
  settings: {
    intervalCm: 2.5,        // گام برش نئون (Cutting Interval)
    maxPieceLengthCm: 500,  // حداکثر طول مجاز یک تکه (معمولاً طول رول)
    minSpacingCm: 1.5,      // حداقل فاصلهٔ مجاز بین دو مسیر نئون
    safetyFactor: 80,       // ضریب اطمینان منبع تغذیه (درصد توان قابل استفاده)
    psuCapacityW: 0,        // ظرفیت منبع (0 = بر اساس پیشنهاد نرم‌افزار)
    nodeTolCm: 0.5,         // تلورانس یکی‌شدن نقاط انتهایی (اتصال)
    joinGapCm: 1.0          // فاصلهٔ «تقریباً چسبیده» → هشدار نیاز به اتصال
  },
  profile: {                // پروفایل نئون (قابل ذخیره و انتخاب)
    name: "Neon Flex 8mm",
    widthMm: 8,
    voltageV: 24,
    intervalCm: 2.5,
    minBendRadiusMm: 30,
    powerPerMeterW: 10,
    rollLengthCm: 500
  },
  paths: [Path],
  texts: [Text],
  mode: "auto"              // "auto" | "manual"
}

Path = {
  id: "p1",
  name: "NEON 01",          // شمارهٔ قطعه روی طرح
  type: "polyline" | "bezier",
  points: [ {x, y} ],       // رأس‌ها بر حسب cm (طول ≥ 2)
  ctrl:  [ {c1:{x,y}, c2:{x,y}} | null ],  // کنترل‌های مکعبی هر قطعه (bezier)
  lockedStart: false,       // قفل نقطهٔ شروع (اتصال به زنجیره)
  lockedEnd: false,         // قفل نقطهٔ پایان
  snapped: false,           // آیا هندسه اصلاح شده تا طول مضرب گام برش شود؟
  snapDelta: 0,             // مقدار تغییر طول (cm)
  origPoints: null,         // هندسهٔ قبل از اصلاح (برای بازگردانی)
  note: ""
}

Text = { id, x, y, text, sizeCm }   // یادداشت/متن روی طرح (خارج از Cut List)

Node (نود اتصال) = { id, x, y, label: "A"|"B"|..., pathIds: [], endIndex: "start"|"end" }

Piece (تکهٔ قابل ساخت) = {
  n: 1,                     // شمارهٔ سراسری
  pathId, pathName,         // مسیر مبدأ
  startS, endS,             // بازهٔ طول قوس روی مسیر (cm)
  lengthCm: 125,            // طول واقعی (مضرب 2.5)
  cuts: 50,                 // تعداد واحد 2.5cm
  startLabel: "A", endLabel: "B",
  points: [ {x,y} ],        // هندسهٔ خروجی تکه (برای رسم/برش)
  isSub: false              // حاصل تقسیم یک مسیر بلند
}

Issue = { level: "error"|"warn"|"info", code, msg, pathId? }
```

**نکته:** نام‌گذاری `NEON 01/02/...` به ترتیب مسیرهاست؛ برچسب `START nn / END nn` روی نقاط ابتدا/انتهای هر مسیر رسم می‌شود و حروف `A, B, C, ...` به نودهای اتصال (نقاط مشترک بین مسیرها) تعلق می‌گیرد — دقیقاً مطابق جدول نمونه:

| شماره | طول | تعداد برش 2.5cm | شروع | پایان |
|------:|----:|----------------:|:----:|:-----:|
| 1 | 125 cm | 50 | A | B |
| 2 | 82.5 cm | 33 | B | C |
| 3 | 47.5 cm | 19 | C | D |

## 4. موتور هندسی

| عملیات | روش |
|---|---|
| طول Polyline | جمع اقلیدسی پاره‌خط‌ها |
| طول Bezier مکعبی | انتگرال \|B′(t)\| با **Quadrature گاوس-لژاندر ۱۶ نقطه‌ای** (دقت ~1e-6 cm) |
| نقطه بر اساس طول قوس | جدول‌بندی نمونه‌های تجمعی + جست‌وجوی دو‌دودویی |
| تقسیم مسیر (Split) | درج رأس در polyline / **de Casteljau** برای Bezier |
| شعاع خم در رأس | شعاع دایرهٔ محیطی سه‌رأس مجاور (پیش، جاری، بعد) |
| شعاع خم خمیده | کمینهٔ شعاع انحنا `R = (1+x′²)^1.5 / |x′y″ − y′x″|` روی نمونه‌های t |
| فاصلهٔ نقطه تا مسیر | کمینهٔ فاصله تا قطعه‌ها (نمونه‌برداری متراکم + تصفیه) |

## 5. الگوریتم اصلاح هندسی (هندسه واقعی، نه گرد کردن عدد)

> «اگر مسیر 83.2 cm است نباید فقط بنویسد 85 cm؛ باید هندسه را اصلاح کند تا طول واقعی به 85 cm برسد و شکل تا حد امکان حفظ شود.»

**گام ۱ — طول هدف:**
```
L      = طول واقعی مسیر (هندسی)
I      = گام برش (پیش‌فرض 2.5 cm)
n      = max(1, round(L / I))
target = n × I                 // نزدیک‌ترین طول قابل‌برش
```
چون `target` مضربی از `I` است، نقاط START و END واقعاً روی **Cutting Pointهای فیزیکی نئون** می‌نشینند.

**گام ۲ — اصلاح هندسه بر اساس وضعیت نقاط ابتدا/انتها:**

- **حالت آزاد (انتهای مسیر به جایی وصل نیست):** تغییر مقیاس یکنواخت حول مرکز ثقل با ضریب `s = target / L`.
  شکل (تناسبات) دقیقاً حفظ می‌شود؛ فقط اندازه کمی تغییر می‌کند.

- **حالت قفل (انتها به مسیر بعدی/قبلی وصل است):** مقیاس عمودی فاصلهٔ رأس‌های داخلی تا **وتر** (خط شروع→پایان) با ضریب `k`:
  ```
  P′ = proj_chord(P) + k × (P − proj_chord(P))
  ```
  سپس **جست‌وجوی دو‌دودویی** روی `k ∈ (0, 8]` تا `length(P′) == target`.
  (طول نسبت به `k` تقریباً یکنواخت است؛ تکرار ۶۰ مرحله‌ای → دقت 1e-9 cm)
  این روش «باد کردن/صاف کردن» شکل است و تناسبات کلی را نگه می‌دارد.

- **حالت خاص `target < chordLength`:** از نظر هندسی با انتهای قفل ممکن نیست → ثبت Issue و هشدار در CHECK DESIGN (طول در Cut List با مقدار واقعی نمایش داده می‌شود، گرد نمی‌شود).

**گام ۳ — علامت‌گذاری:** مسیر `snapped=true`، اختلاف در `snapDelta` ذخیره و هندسهٔ قبلی در `origPoints` نگه داشته می‌شود (قابل بازگشت).

## 6. نقاط برش، تقسیم قطعات و ساخت Cut List

1. روی هر مسیر، مختصهٔ طول قوس `s` مبنا قرار می‌گیرد. مرزهای تکه‌ها روی `s = k × intervalCm` هستند.
2. اگر `L > maxPieceLengthCm`: مسیر به چند تکهٔ زیرمجموعه (`isSub`) با مرزهای روی گام برش تقسیم می‌شود. نقطهٔ تقسیم با برچسب پیوند (Join) علامت می‌خورد.
3. **نودهای اتصال:** نقاط انتهایی مسیرهای مختلف که فاصله‌شان `< nodeTolCm` است یک نود مشترک‌اند و به ترتیب ظهور حروف `A, B, C, ...` می‌گیرند.
4. هر تکه یک سطر جدول:
   `شماره | طول | تعداد برش 2.5cm | شروع | پایان`
   که `تعداد برش = طول / 2.5` (تعداد واحدهای 2.5cm داخل تکه).
5. روی طرح: `NEON nn` وسط هر مسیر، `START nn` (سبز) و `END nn` (قرمز) روی ابتدا/انتها، حروف نودها روی نقاط اتصال.

## 7. محاسبهٔ منبع تغذیه

```
Total Neon (m) = مجموع طول همهٔ مسیرها / 100
Power (W/m)    = مقدار قابل تنظیم کاربر (پیش‌فرض 10)
Total Power (W)= Total Neon × Power
ضریب اطمینان  = safetyFactor% (پیش‌فرض 80٪ → 20٪ هدروم)
PSU پیشنهادی   = ceil(Total Power / (safetyFactor/100)) → رند به بالا به توان‌های استاندارد
جریان (A)      = Total Power / Voltage
```
توان‌های استاندارد: `30, 40, 60, 75, 100, 120, 150, 200, 240, 320, 350, 400, 500, 600, 750, 1000, 1500`
اگر کاربر ظرفیت منبع را دستی وارد کرده باشد، CHECK DESIGN آن را با توان کل مقایسه می‌کند.

## 8. بهینه‌سازی پرت نئون (Cutting Stock / Bin Packing)

- ورودی: طول تکه‌ها + طول رول (`rollLengthCm`، مثلاً 500 cm).
- الگوریتم: **First Fit Decreasing (FFD)** — مرتب‌سازی نزولی طول‌ها، قرار دادن هر تکه در اولین رولی که جا دارد؛ در صورت عدم‌جایابی، رول جدید.
- (در صورت نیاز به کیفیت بالاتر، قابل ارتقا به Best-Fit-Decreasing یا جست‌وجوی ترکیبی.)
- خروجی: تعداد رول، تخصیص تکه‌ها به هر رول، پرت هر رول، پرت کل و درصد پرت.

مثال: `Roll=500` و قطعات `185, 125, 90, 75` → یک رول، پرت `125 cm`.

## 9. CHECK DESIGN (فهرست قواعد بررسی نهایی)

| # | قواعد | سطح |
|---|---|---|
| 1 | طول مسیر/تکه مضرب گام برش نیست و اصلاح هندسی ممکن نبود | error |
| 2 | فاصلهٔ دو مسیر کمتر از `minSpacingCm` | error |
| 3 | شعاع خم (رأس یا خمیدگی) کمتر از `minBendRadius` | warn |
| 4 | مسیر باز/ناقص (کمتر از ۲ نقطه یا طول تقریباً صفر) | error |
| 5 | تکه بدون نقطهٔ شروع/پایان معتبر (نود نام‌گذاری‌نشده) | warn |
| 6 | توان کل بیش از ظرفیت منبع تغذیه | error |
| 7 | طول تکه بیش از `maxPieceLengthCm` | error |
| 8 | نقاط «تقریباً چسبیده» که به هم وصل نیستند (`joinGapCm`) | warn |
| 9 | نقطهٔ تقسیم/شروع/انتها خارج از گام برش واقعی | error |

نتایج در پنجرهٔ CHECK DESIGN با امکان انتخاب مسیرِ مشکل‌دار نمایش داده می‌شود.

## 11. حالت‌های AUTO و MANUAL

- **AUTO MODE:** شماره‌گذاری، اصلاح طول‌ها (Snap)، تقسیم تکه‌های بلند، ساخت Cut List و بهینه‌سازی پرت به‌صورت خودکار پس از هر ویرایش.
- **MANUAL MODE:** کاربر کنترل کامل دارد:
  - جابه‌جایی رأس‌ها و تغییر شکل مسیر
  - تغییر جهت مسیر (Reverse)
  - تقسیم دستی در نقطهٔ دلخواه (Split)
  - قفل/آزاد کردن نقطهٔ شروع و پایان
  - اجرای دستی «Snap Lengths» و «Optimize Cuts»

## 12. نقشهٔ راه (MVP ← پیشرفته)

**MVP (این نسخه):** ابزارهای رسم (Select, Pen, Line, Bezier, Text, Split, Measure, Import)، اصلاح هندسی طول، Cut List چاپی، شماره‌گذاری NEON/START/END، محاسبهٔ برق، FFD پرت رول، خروجی SVG/DXF/PNG/CSV/PDF، پروفایل نئون، CHECK DESIGN، ذخیرهٔ پروژه.

**اضافه‌شده (نسخهٔ فعلی):**
- **تریس تصویر:** هر عکس → مرکزخط نئون. خط‌لوله: `binarize` (آستانه + معکوس) → **Zhang-Suen thinning** (اسکلت 1px) → **پیمایش گراف اسکلت** (گره‌ها/انتهاها/حلقه‌ها) → **RDP** → نرم‌سازی Catmull-Rom → Bezier → جاگذاری در تابلو.
- **طرح دوبل / کانال برش:** آفست پلی‌خط با میتر محدودشده (`offsetPolyline`) به اندازهٔ نصف عرض کانال در دو سمت مرکزخط → خروجی `CUT DXF` / `CUT SVG` برای برش‌دهنده.
- **نمونه‌های حرفه‌ای:** دایره + متن فارسی «نئون» (متن هم از همان خط‌لولهٔ تریس رد می‌شود)، گالری اشکال نرم (ستاره، قلب، برق، اسمایلی، موج، دایره).

**پیشرفته (آینده):** ویرایشگر کامل گره‌های Bezier (دستگیره‌ها)، import کامل SVG با transform، رفع تقاطع خود-آفست، بهینه‌سازی BFD/جست‌وجوی ترکیبی پرت، خروجی G-code، همگام‌سازی ابری، نمای سه‌بعدی پیش‌نمایش نوری، چندزبانه‌سازی کامل رابط.
